Tag Merge UX — 5 Design Options

Issue #338 — How users merge two tags into one, including target selection, merge preview, and confirmation.

Flow: User selects "Merge into..." from a tag's context menu → selects a target tag → sees preview with counts → confirms merge.

Sample data: Source tag "frontend" (3 tasks, 4 notes, 2 meetings = 9 items). Target tag "architecture" (2 tasks, 4 notes, 2 meetings = 8 items). 3 items have both tags (overlap).

Why recommended: The two-step flow keeps each screen focused — step 1 is purely about selection with search, step 2 is purely about review. The table view makes the math transparent (where did 3 items go? Duplicates). The searchable tag list handles large tag counts better than a dropdown. Back button lets users change their mind without starting over.

+ Focused screens — selection and review are separate concerns
+ Searchable tag list scales to hundreds of tags
+ Table breakdown makes merge math transparent and trustworthy
+ Back button lets users change target without restarting
+ Stepper indicator shows progress clearly
- Two clicks to complete vs. one in single-dialog options
- Slightly more complex to implement (stepper state)

- Drag & drop is not discoverable without onboarding
- Not accessible — keyboard users and screen readers need fallback
- Fiddly on mobile — touch drag targets are too small
- Requires still opening a menu/dialog as fallback for accessibility

Note Feature - Layout & Component Design

Exploring layouts for the Note feature with rich text editing, checkboxes that become tasks, and tag support

Context: Note Domain Model

Key Features to Support
  • 1. Rich Text Content: Opaque string stored as TipTap JSON, ProseMirror, or Markdown (editor-agnostic)
  • 2. Checkboxes: Extracted from content, can be converted to Tasks. Each has ID, text, and isChecked state
  • 3. Tags: Note-level tags that tasks inherit when created from checkboxes
  • 4. Timestamps: CreatedAt and UpdatedAt for tracking modifications

The Note serves as a scratchpad where users capture thoughts, then promote checkboxes to full Tasks when ready.

Comparison: Layout Options

Option Pattern Pros Cons Best For
1. Split View (Recommended) Apple Notes / Bear Fast note switching, full editor, works on mobile Takes full screen, separate from tasks Primary notes workflow
2. Card Grid Google Keep Visual overview, quick scanning Less room for content, needs modal for editing Many short notes
3. Single Note Focus Notion Best writing experience, beautiful Slow to switch notes, more clicks Long-form content
4. Integrated with Tasks Unified workspace Direct drag-to-task, single view Complex UI, may be overwhelming Power users, task-heavy workflow
5. Floating Quick Note Capture-first Fast capture without context switch Notes feel secondary, limited space Quick thoughts while in tasks
6. Tab Navigation Tasks | Notes tabs Clear separation, simple mental model Extra click to switch, no unified view Users who prefer separation

Recommendation: Option 1 - Split View

Why This Option?

  • • Proven pattern used by Apple Notes, Bear, Notion, Obsidian
  • • Fast navigation between notes while keeping editor visible
  • • Works well on both desktop and mobile (responsive)
  • • Bottom action bar makes checkbox-to-task conversion discoverable
  • • List can show tags, checkbox counts, and timestamps at a glance
  • • Can evolve to support folders/organization later

Implementation Approach

  • • Editor: TipTap with custom checkbox extension
  • • Components: PrimeNG Splitter for resizable panels
  • • Mobile: Full-screen list → Full-screen editor (navigation)
  • • Toolbar: Option C (floating/bubble) for clean writing experience
  • • Tags: Reuse existing tag picker from task cards
  • • State: Signal-based with computed for filtered/sorted notes

Alternative Consideration: Option 6 (Tab Navigation)

If the Split View feels too heavy, Tab Navigation is a simpler alternative. It keeps Notes and Tasks completely separate, which may be preferable if users don't frequently convert checkboxes to tasks. The tabs could be added to the existing header navigation.

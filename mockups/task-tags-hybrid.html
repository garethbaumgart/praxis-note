Comparison: Overflow Strategies

Solution Visible Tags Pros Cons
A. Limit + Overflow (Recommended) 3 tags + "+N" Predictable height, scannable, expandable May hide important tags
B. Horizontal Scroll All (scrollable) All tags accessible, fixed height Hidden content, requires interaction
C. Two-Row Max ~5-6 + "+N" Shows more tags, bounded height Variable height, slightly complex
D. Single Tag + Count 1 tag + "+N more" Most compact, predictable Least informative at a glance

Recommendation: Solution A - Limit + Overflow Count

Why This Solution?

  • * Predictable card height (always single row)
  • * Shows enough tags to be useful (3 is the sweet spot)
  • * Clear affordance that more exist (+4 is clickable)
  • * Expanded state allows full management
  • * Consistent with how other apps handle this (Jira, GitHub)

Implementation Rules

  • * Show max 3 tags in collapsed state
  • * If 4+ tags: show 3 + "+N" button
  • * Click +N expands to show all with X buttons
  • * Expanded state shows "Less" button to collapse
  • * Plus button always visible for adding
  • * Tags ordered by most recent? Or alphabetical?

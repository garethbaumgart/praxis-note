## Context

The meetings feature currently includes three interconnected subsystems layered on top of core meeting analysis: behavioral analysis (generated by AI alongside summary/decisions), reflection (post-meeting self-assessment), and insights (dashboard aggregating behavioral data across meetings). These subsystems are tightly coupled — insights depends on behavioral analysis data, and the Johari window requires both behavioral analysis and reflection data.

The core meeting analysis (summary, key points, decisions, action items) is independent of all three subsystems and remains untouched.

## Goals / Non-Goals

**Goals:**
- Remove all reflection, behavioral analysis, and insights code from the codebase
- Drop associated database columns via migration (clean break)
- Simplify the AI analysis prompt to stop requesting behavioral data
- Leave the codebase in a state where these features could be re-introduced as standalone, well-designed capabilities

**Non-Goals:**
- Redesigning meeting analysis — the summary/key-points/decisions/action-items flow is unchanged
- Preserving existing behavioral/reflection data — this is a destructive migration by design
- Building replacement features — simplification only

## Decisions

### 1. Deletion order: backend-first, then frontend

Remove backend code first (domain → application → infrastructure → web), then frontend. This avoids a state where the UI references non-existent APIs. The database migration is created last since it's the final irreversible step.

**Alternative considered**: Frontend-first removal. Rejected because leaving orphaned backend code is lower-risk than leaving UI that calls missing endpoints.

### 2. Single database migration to drop all 4 columns

One migration drops `BehavioralAnalysis`, `ExcludeFromInsights`, `ReflectionData`, and `ReflectionSubmittedAt` together. These columns are all part of the same removal scope and there's no reason to drop them separately.

**Alternative considered**: Separate migrations per feature (reflection vs behavioral). Rejected — adds unnecessary migration churn for a single logical change.

### 3. Modify AI prompt rather than post-process

Remove the behavioral analysis section from the AI prompt in `AnthropicMeetingAnalyzer.cs` rather than generating it and discarding. This reduces token usage and latency.

### 4. Delete insights feature entirely (no shell/placeholder)

Remove the insights directory, routes, sidebar link, and home widget completely rather than leaving a "coming soon" placeholder. Dead code is worse than no code.

### 5. Remove the feature notification migration data

The `20260130120000_AddNotificationSelfReflectionPrompts` data migration inserted a feature notification. Create a corresponding data migration to clean up the notification row, keeping the migration history clean.

## Risks / Trade-offs

- **Data loss**: Dropping columns destroys existing behavioral analysis and reflection data permanently. → Acceptable per user decision. Data can be regenerated via re-analysis if features return.
- **Migration on production**: Column drops on PostgreSQL are fast (metadata-only) but irreversible. → Standard deployment; rollback would require restoring from backup.
- **Insights goals data**: Users may have created behavioral goals. These will be orphaned when the goals table references are removed. → Need to check if goals have their own table or are stored elsewhere; clean up accordingly.
